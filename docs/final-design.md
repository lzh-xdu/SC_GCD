# 最终设计文档：SystemC 流式 GCD 处理器（SC_GCD）

更新：2026-09-10。四阶段全部实现并通过实测；本文替代 2026-09-07 的「约束与优化目标」版本（作业 4 当时待实现），题目约束与统一约定经压缩保留，原文见 Git 历史。

## 1. 系统概述

输入文件每行两个有符号 32 位整数，系统逐行计算 GCD 并按输入顺序每行输出一个非负结果；另存性能统计。四个可执行模型按作业递进，后者保留前者的功能与时序语义：

```
作业1   Parser → [FIFO] → Transform(两级流水) → [FIFO] → Compute → [FIFO] → Output
作业2   Transform → Compute 改为 valid/ready/data 显式握手（去掉中间 FIFO）
作业3   Dispatcher(择闲) → Compute×2 → 结果FIFO×2 → Collector(按序窗口退休)
作业4   同作业3结构，去掉时钟，改为稀疏事件调度，模拟语义不变
```

公共支撑层与各阶段解耦：`model/functional`（纯数值：取幅值/排序/取余）、`model/timing`（周期单位、GCD 延迟计划）、`model/instrumentation`（观察者统计）；作业 4 拥有独立副本，保证 1～3 阶段不随后续修改变化。命令行：`INPUT OUTPUT STATS [DEPTH=2] [EVENTS|-] [OUTPUT_PERIOD=1] [MAX_CYCLES] [RESULT_DEPTH=2] [WINDOW=8] [SEED=1]`（位置参数，各阶段取其前缀）。

## 2. 关键时序契约

- 周期 1 ns、首沿编号 1；所有模块每沿最多接收/发出一项；**完成当前任务的沿不能接收下一项**；FIFO 本沿写入/释放的空间下一沿才对对端可见。
- Transform 两级流水（幅值→排序）固定 2 周期，每周期最多穿过一项；Compute 每实例一次一项，延迟 `L = Σ max(1, bits(a)−bits(b)+1)`（Euclidean 每步），`b=0` 时 `L=0`。
- **实测契约**：作业 1 全部场景满足 `T = B + N + 5`（总周期＝忙周期＋任务数＋启动/排空常数），验证了上述接受/完成节拍。
- 有符号输入先拓宽再取绝对值（覆盖 INT32_MIN）；输出严格按输入编号顺序，乱序完成由窗口缓冲重排。
- **Model Assumption（spec 未规定）**：`gcd(a,0)=a`、`gcd(0,b)=b`、`gcd(0,0)=0`；零延迟任务不占用忙周期。
- 空文件合法；非法行失败退出；在途任务全部排空后仿真结束；被动统计不参与流控。

## 3. 关键设计决策

| 决策 | 选择与理由 |
|---|---|
| 运行时契约 | `assertCondition` 抛异常代替 `assert`，Debug/Release 行为一致；公开接口错误与内部不变量分类（runtime/logic_error） |
| 统计口径 | EventRecorder 观察者模式：记录事件边界但不改变调度；任务延迟按五边界四段（precompute/compute/result_wait/delivery）＋端到端，报均值/P95/最大值 |
| 作业 3 派发 | 择闲优先（都空闲时固定种子随机打破平局）＋按任务编号预留有界窗口（W 个信用）＋队头按序退休；固定轮转版本保留作基线。实测择闲+窗口在混合负载比轮转少 1415 周期 |
| 作业 4 调度 | 集中 `runEvents`：各模块报告 `nextDelay`，系统跳到最近期限一次推进；跳过区间用 `accountSkipped` 加权补齐统计。禁止固定周期轮询 |
| 源码分层 | functional/timing/instrumentation 职责分层（2026-09-09），数值与时序可独立复用 |

## 4. 验证方法

每次测量运行均用独立 `math.gcd` 参考校验输出值与顺序；CTest 25/25（Windows MinGW 与 WSL g++ 双工具链、Release/Debug）；作业 4 与作业 3 窗口模型按 9 场景比较输出文件与完整统计哈希一致、2 场景事件 Trace 逐字节一致；同配置重复运行及 Trace 开/关的统计哈希一致（确定性与被动观察者契约）。作业 3、4 各保留至少一个主动暴露的真实缺陷案例（B-006/B-011 等，见 [缺陷记录](defects.md)）。

## 5. 主要实测发现（2026-09-10，Linux/WSL Release；详见 [实测结果](metrics-results.md)）

1. **容量不是吞吐杠杆**：混合负载下 FIFO 深度 1→32，总周期不变（476083），阻塞率恒 97.9%（瓶颈＝Compute 每任务 `L+1` 拍的接受率）；更深的缓冲只把端到端 P95 从 202 推高到 1705 拍（纯排队延迟）。
2. **输出节拍决定吞吐上限**：吞吐精确等于 `1/max(L+1, P)`；短任务负载 P=16 时 T=16×N，阻塞率升至 93.7%，背压沿「输出→结果 FIFO→Compute→握手→Parser」传播（时间线证据）。
3. **双实例近线性加速，但保序是条件**：短/长/混合负载加速比 2.00×、并行效率≈1.0；零延迟负载无收益（无可并行计算）；长短偏斜负载仅 1.06×——队头长任务迫使后续短结果滞留窗口 75 拍，且 W=8 信用耗尽阻塞派发。窗口 W=1 时比单实例还慢 44%，W≥块长（21+2）后信用阻塞消失、恢复 2.0×。
4. **保序资源代价**：结果载荷 96W bit＋有效位 W bit（W=32 时 3104 bit）；窗口预留与结果占用峰值随 W 达到块内并发上限（W=32 时 23/21）。
5. **事件模型等价且在稀疏场景大幅提速**：9 场景功能与时序完全一致；主机耗时（进程口径）长计算/慢输出/稀疏等待快 3.3×/22×/30×；连续零延迟近似持平（0.95×，无可跳过周期）；Windows 入口径基线为 5.8×/71×/329×（口径不同，均已保留）。
6. **B-011（平台无关）**：事件模型开详细 Trace 时反超变慢（混合小样本 +481% vs 时钟 +317%），根因是对跳过区间逐周期补齐控制行并排序缓存；功能时序不受影响。

## 6. 已知问题与边界

- B-011 Trace 性能/内存设计问题已复现并记录，优化未实施。
- 未测量项：缓冲满载占比、窗口驻留时长分布（仅有时间线样本）、Linux 侧 delta 轮次（沿用 Windows 证据）；主机耗时 7 样本只报中位数＋四分位。
- 主机指标是进程/入口口径，与模拟硬件吞吐分开陈述；资源位数为成本代理，非综合后面积/功耗。
