# 最终设计：约束与优化目标

更新：2026-09-07。这是提交设计的统一入口；当前已实现作业 1～3，作业 4 待完成，不代表全作业已验收。

## 不可改变的约束（题目）

- 输入每行两个有符号 32 位整数；Parser 每周期最多读取并发送一组。
- Transform 依次取绝对值、比较交换，使 a≥b；两级变换无阻塞延迟 2 周期，最高每周期一组。
- Compute 使用 Euclidean 取余；每步耗时 `max(1, bits(a)-bits(b)+1)`，总延迟为各步之和；每实例一次一项。
- 作业 1～3 同一时钟上升沿推进；完成当前任务的沿不能接收下一项；缓冲有限，背压时保持数据；最终结果严格按输入顺序输出。
- 作业 2 使用 valid/ready/data；作业 3 使用两个独立 Compute 并实现保序；作业 4 将整个系统改为事件驱动，禁止固定周期轮询，保持作业 3 功能、延迟及流控语义。
- 功能文件只写最终结果，另存性能统计；报告周期、吞吐、计算利用率、缓冲占用，以及握手阻塞、双实例/保序开销；作业 4 比较实际仿真效率与开销。
- 按 1→2→3→4 实现验收；时间不足优先完善已完成阶段。持续记录设计、调试、AI 要求/修改/真实错误并提交公开 Git；作业 3、4 各主动暴露并处理至少一个真实问题。候选人须理解全部代码。

## 当前设计选择（不是额外题目要求）

| 阶段 | 数据路径与关键选择 |
|---|---|
| 1 | 四模块经 FIFO 相连；FIFO 默认深度 D=2；两级流水各保存一项 |
| 2 | 移除 Transform→Compute FIFO，替换为显式握手；其余延迟不变 |
| 3 原版 | 固定轮转派发、按编号轮转收集；保留作性能基线 |
| 3 当前 | 优先选择空闲单元；都空闲时固定种子随机选择；按任务编号预留有界窗口并顺序退休；D=2、每单元结果 FIFO R=2、窗口 W=8、种子 1 |
| 4 待实现 | 保留当前阶段 3 配置与边界语义，以事件跳过无变化时间 |

统一约定：周期 1 ns，首沿编号 1；FIFO 本沿写入/释放空间到下一沿才能被对端使用；结果交付沿也不接新项（当前简化限制）。`gcd(a,0)=abs(a)`、`gcd(0,0)=0`，零次取余 L=0；先扩宽再取绝对值以覆盖 INT32_MIN。空文件合法；格式/范围错误失败退出；所有在途任务排空后结束。

## 优化目标与比较原则

1. **先正确且可解释**：数值、顺序、时序、容量和握手保持均由独立参考验证，不能修改规定的计算耗时换取提速。
2. **减少完成整个工作负载的周期，提高吞吐**：同时报告统一任务延迟的均值/P95/最大值，避免只改善吞吐却隐藏尾部等待。
3. **减少可避免的等待**：区分计算忙、结果堵塞、轮转错失空闲单元、窗口限制与保序等待；计数可能重叠，不能直接相加为损失周期。
4. **控制资源代价**：比较计算实例数、FIFO/窗口容量、逻辑有效载荷位数及有效位；这些是成本代理，不能冒充综合后的面积、功耗或频率。
5. **单变量、同负载对照**：固定输入、输出节拍、工具链和随机种子，记录资源差异；覆盖零/短任务、连续斐波那契、长短混合、10 组固定种子随机数据与慢输出。允许记录退化。
6. **阶段 4 单独优化仿真速度**：同配置比较模型时序，再在相同日志/统计设置下重复测主机运行耗时；不将主机速度与模拟硬件吞吐混为一谈。

一周约 21 小时为初始预算，实际剩余时间未统计。当前阶段 3 真实缺陷证据已保留；阶段 4、用户理解验收和公开可访问性仍待完成。
