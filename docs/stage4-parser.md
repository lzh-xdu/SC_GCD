# 作业 4：Parser 脱离时钟

2026-09-10；用户澄清采用原输入节拍，不采用每个 delta cycle 输入一对。当前是渐进迁移：Parser 已使用定时与 FIFO 事件，其他模块及统计观察仍使用原时钟。

## System 与 Parser

- `System::connectModules()` 删除 Parser 时钟绑定；Parser 删除 `m_clk` 端口。
- Parser 以 `SC_THREAD(run)` 在 1 ns 首次读取并发送，之后最快每 1 ns 一对。
- FIFO 满时等待 `data_read_event()`，不读下一行、不缓存额外任务、不做固定周期轮询。
- 空间释放后对齐严格晚于当前时刻的下一个整数 ns：5 ns 释放则 6 ns 输入，5.5 ns 释放也为 6 ns。保留旧 FIFO 同拍释放、下一拍重用的语义。
- 每个输入边界的定时等待后再等待一个 delta，使写入与旧上升沿处理处于相同求值阶段；FIFO 在随后的 update 阶段可见，当前仍有时钟的 Transform 不会提前一拍接收。
- EOF 仍在有空位的输入边界检查，随后线程退出；非法输入检查及任务编号保持。

`waitForInputBoundary()` 管时间，`readAndSend()` 管读取和校验，`run()` 串联输入与背压等待。1 ns 定时是外部输入速率，不能据此把整个系统称为无时钟事件模型。后续改造 Transform 时还需核对同一时刻的求值和 FIFO 更新约定。

## 验证与限制

- Release/Debug 全量 CTest 各 14/14；完善事件时间顺序断言后，两种配置的作业 4 测试各 2/2 再次通过。
- 新增无时钟 `stage4_parser_timing`：首次 1 ns；满 FIFO 长时间无周期唤醒；5.5 ns 释放、6 ns 恢复；8 ns EOF 后无继续唤醒。通过 delta 计数检查无空转。
- 新旧全系统各 31 个有效场景、9 类非法输入；比较各 276 份产物。结果和统计逐字节一致，事件值、时间和各流顺序一致，仅允许 Parser 与其他进程在同一时刻的日志行交错变化。
- 初始逐字节比较真实失败，原因是它把独立进程的同拍日志写入顺序当成了模型语义；保留原始证据，见 [B-009](defects.md#b-009parser-事件迁移暴露日志比较过度约束)。没有把这次测试约束问题算作作业 4 已完成的处理器缺陷案例。

证据见 [验证记录](evidence/stage4-parser/validation.md)。原始逐周期副本仍可从提交 `1f252ab` 恢复；未修改作业 1～3，未进行主机性能比较。
