# 第一天：时钟、波形与仿真生命周期

日期：2026-09-06。对应 src/day01_basics.cpp，依据本地官方 SystemC 3.0.1 的 sc_clock.h、sc_trace.h、sc_simcontext.h/.cpp 核对。这里只解释既有程序，没有新测试执行。

## 1. 时钟构造

`sc_clock clk("clk", sc_time(10, SC_NS), 0.5, sc_time(5, SC_NS), true)`：

| 参数 | 含义 |
|---|---|
| clk | C++ 变量名 |
| "clk" | SystemC 对象名称 |
| 10 ns | 完整时钟周期，上升沿到下一上升沿 |
| 0.5 | 占空比，高电平占周期的 50%，即 5 ns |
| 5 ns | 第一次边沿的仿真时间 |
| true | 第一次边沿为上升沿，而非下降沿 |

本例 0～5 ns 为低电平，5 ns 上升，10 ns 下降，15 ns 上升，20 ns 下降，25 ns 上升。
周期 10 ns 对应模型频率 100 MHz；不代表电脑必须按现实时间等待或以该频率执行。
第一次沿放在 5 ns，给时间零测试线程写入初值留下明确的间隔。

## 2. 创建波形文件

`auto* trace = sc_create_vcd_trace_file("day01_basics")` 返回由该 API 管理的 sc_trace_file 指针，建立 VCD 记录对象，输出名自动追加 .vcd。
VCD 是 Value Change Dump，记录已注册信号随时间变化的值，不是普通 printf 日志，也不自动记录所有变量。
文件位于进程运行目录；项目脚本在 build 下运行，所以这里生成 build/day01_basics.vcd。
实现可延迟实际打开/初始化文件，不应依赖创建函数返回后文件已经完整落盘。

## 3. 波形时间单位

`trace->set_time_unit(1, SC_NS)` 设置 VCD 的时间标尺为 1 ns。例如文件时间戳 #15 表示 15 ns。
它不改变时钟周期、不设置内核时间分辨率、不要求每 1 ns 采样一次。
1 ns 适用于本例整数 ns 的变化；若存在更细的变化，应选择足够细的波形单位。

## 4. 注册信号

`sc_trace(trace, clk, "clk")`：trace 指向目标波形文件，第二个 clk 是被观察对象，字符串 "clk" 是波形显示名。
对象名和波形显示名可以不同。该调用注册后续跟踪，不只是保存此刻的一个值。
其余三次调用记录输入连接、内部 stage1、输出连接，便于对照传播过程。
本例未启用 delta-cycle 跟踪；不要期待普通 VCD 展开同一时刻的全部 delta 内部步骤。测试的 before/after 文本输出更适合当前学习问题。

## 5. 启动仿真

`sc_start(sc_time(100, SC_NS))` 从当前仿真时刻启动/继续指定时长，本例从 0 ns 开始，预算到 100 ns。
调用期间，内核执行已注册进程、更新信号、处理事件并推进仿真时间；sc_main 暂不执行后面的语句。
100 ns 是模拟时间，不是电脑运行耗时。可因 sc_stop 或 sc_pause 提前返回。
本例测试线程在 25 ns 调用 sc_stop，所以不会正常运行满 100 ns；100 ns 用作未按预期结束时的仿真时间上限。
若卡在不让出执行权的 C++ 死循环或无穷零时间事件中，模拟时间上限不能保护它；CTest 另外设置了实际运行时间 TIMEOUT 10 秒。

## 6. 关闭波形

`sc_close_vcd_trace_file(trace)` 完成并关闭对应 VCD 记录、释放记录对象。此后不能再使用 trace 指针。
它不停止仿真；这里在 sc_start 返回后清理波形资源。

## 7. 是否调用过结束阶段

`sc_end_of_simulation_invoked()` 检查内核是否已进入/调用结束仿真阶段，不能证明模型计算正确。
本例 sc_stop 触发结束阶段；如果仅达到 sc_start 的 100 ns 时长而返回，通常只是结束本次运行区间，结束阶段标记仍为 false。
因此本例检查 false 时报告测试未按预期主动结束，返回失败。
这个判断单独不能证明所有检查都执行过：其他位置提前 sc_stop 也会置位。当前代码只有测试线程的既定停止点，再结合 failures 和 25 ns 检查判定结果；以后多个停止点时应另加 tests_completed 标记。

## 8. dont_initialize

紧随 SC_METHOD 注册和 sensitive 配置调用，作用于最近注册的进程。
SC_METHOD 默认会在初始化阶段执行一次，即使此时没有敏感事件；dont_initialize 取消这次默认执行，但不取消之后的上升沿触发。
本例 capture/forward 分别配置一次，使它们第一次实际执行发生于 5 ns 的上升沿。
它不负责寄存器清零、不代替复位，也不阻止时间零真实发生的敏感事件触发进程。
TB 的 SC_THREAD 没使用它，因此在时间零开始运行、写入 10，随后 wait 等待上升沿。

## 整体次序

构造对象/接线/注册进程 → 设置波形跟踪 → sc_start → 时间零 TB 写输入 → 5/15/25 ns 上升沿与检查 → TB 调用 sc_stop → sc_start 返回 → 关闭波形 → 检查结束状态和 failures → 返回退出码。
